# Four-part website prompts

Owner workflow updated 2026-11-05. Target working profile: GPT-5.6 terra, medium.
Select that profile in the app if available; these prompts do not switch models.
No stronger model or external ChatGPT API is required by this workflow.

Read `PROJECT_RULES.md` for the full owner policy. Use these four prompts in order,
one at a time, in the same domain project. Each authorizes real implementation of
its whole part. Ask only for essential missing inputs; fix routine issues without
extra repair prompts. Stop at that part's boundary and record the next step.

## Permanent rules in easy words

- First name the working folder after the exact supplied domain; preserve the master.
- Fully rewrite the actual content for the new game, including article bodies.
  A game-name swap, changed config, new titles or a plan alone is not a conversion.
- Preserve the template layout, section order, navigation, sliders and responsive
  structure. Keep the recorded Zadeyo dark/purple/white palette; its copy and art
  are not content sources. Fix the existing light theme without redesigning.
- HWID: $50 USD / 30 days, $150 lifetime. Other products: $35 / 30 days, $150 lifetime.
- Confirm the game's product lineup and exact referral URL per product. Preserve
  plan selection. UGC means Unban & Governance Control, an account-appeal product.
- Ask for game images after the commercial rewrite, then competitor article URLs
  after the image step. Use supplied inputs immediately when already present.
- Read competitors, research current primary sources and write independently.
  Main and utility articles must fit this game; never invent features/error meanings,
  compatibility, availability, tests, reviews or guaranteed results.
- Create useful forum topics with clearly labeled publisher/editorial answers.
  No fake customers, votes or testimonials. Preserve the existing comment layout;
  extend the baseline contract deliberately during the conversion.
- Finish English content, URLs and internal links before translating all content
  into es/de/fr. English is primary/unprefixed. Retain shared slugs.
- One sitemap.xml: all four languages, priorities, reciprocal alternatives and
  English x-default, matching HTML source. Each translation is self-canonical.
- Remove old-game deployed data, artwork, URLs, links, aliases and redirects.
  Use contextual locale-correct links and distinct page intents.
- Keep one PROJECT_STATUS.md and small completed batches. Never claim unrun tests.
  Target actual 100/100 Lighthouse SEO and applicable Seobility checks; use real
  Screaming Frog crawl evidence. No backlink campaign or automatic publishing.

## Why the staged install and audit notes matter

The template's content gate needs the complete four-locale pack before the new
origin can be finalized. Parts 1–2 must still produce real rewritten English copy
and full editorial bodies; they are intermediate work, not a finished conversion.
Part 3 installs/verifies the complete result. No template safety check needs removal.

Lighthouse scores cover specific audits, not every aspect of SEO. For example,
its [meta-description check](https://developer.chrome.com/docs/lighthouse/seo/meta-description)
does not assess description quality. [Performance scores also vary with test conditions](https://developer.chrome.com/docs/lighthouse/performance/performance-scoring).
Use [Seobility's actual reports](https://www.seobility.net/en/seocheck/) and
[Screaming Frog's crawl/export tools](https://www.screamingfrog.co.uk/seo-spider/user-guide/general/)
when available; distinguish local checks from public/live checks.

For a new workspace, carry AGENTS.md, PROJECT_RULES.md and this file into it.
Use the domain folder for later chats; PROJECT_STATUS.md preserves progress.
These files carry instructions, not account-wide memory or model training.
